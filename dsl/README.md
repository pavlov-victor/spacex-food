# Версии Dify workflow

Теперь два отдельных workflow с независимой нумерацией:

- [menu/0.0.3.yml](menu/0.0.3.yml) — `spacex-menu`: фото меню → продукты и категории. [Инструкция](menu/README.md).
- [product/0.0.5.yml](product/0.0.5.yml) — `spacex-product`: английский контент и карточки, три референса (блюдо/стол/дизайн), отдалённая композиция и подробные плашки. [Инструкция](product/README.md).

Исторические версии меню `0.0.1.yml` и `0.0.2.yml` находятся в `menu/`. Новые версии создаём в `menu/` и `product/`; существующие версии не перезаписываем. Первый релиз каждого workflow — `1.0.0.yml`.

Каждая версия хранится отдельным файлом: `0.0.1.yml`, `0.0.2.yml`, `0.0.3.yml` и далее. Первый релиз — `1.0.0.yml`.

Сохранённые версии не перезаписываем: изменения вносим в следующий файл. Номер файла — версия нашего workflow; внутреннее поле `version` в YAML относится к формату Dify DSL и не меняется ради нумерации файлов.

| Версия | Изменения | Проверка |
| --- | --- | --- |
| 0.0.1 | Исходный экспорт `spacex-food.yml`, полученный 2026-09-12, без изменений | Копия совпадает с оригиналом; запуск в Dify не проверен |
| 0.0.2 | 1–5 фото → Grok vision → проверка JSON → продукты и категории | YAML, связи графа и Python-валидатор проверены локально; импорт и запуск в Dify не проверены. x.ai API возвращает 403: у команды нет кредитов/лицензии |

Для каждой следующей версии добавляем строку с изменениями и результатом проверки. Секреты в файлы не включаем.

## Запуск 0.0.2

1. В Dify установите официальный [провайдер xAI](https://marketplace.dify.ai/plugin/langgenius/x) (`langgenius/x`) и настройте его API Key в Model Providers. Ключ из локального `.env` автоматически в Dify не передаётся. DSL не содержит секретов и не устанавливает плагин автоматически.
2. Импортируйте `0.0.2.yml`. В LLM-узле выбрана `grok-4-fast-non-reasoning`: в [официальной конфигурации провайдера](https://github.com/langgenius/dify-official-plugins/blob/main/models/x/models/llm/grok-4-fast-non-reasoning.yaml) она поддерживает vision и JSON. Проверьте доступность модели в своём аккаунте.
3. Передайте в **menu_images** от 1 до 5 JPG/PNG одного меню, в порядке страниц. Это новый вход типа `file-list`, заменяющий одиночный `menu_image` из 0.0.1. Фото передаются в vision явно из Start; общий загрузчик `sys.files` не используется.
4. Запустите Preview. Проверьте названия, цены, порции и категории по оригиналу. После успешной проверки опубликуйте workflow и обновите схему входов MCP в Dify.

Выходы: `products` (массив объектов), `categories` (массив объектов), `warnings` (строки), `status` (`ok`, `needs_review`, `empty`), `schema_version` и `menu_json` (весь результат JSON-строкой).

Категория: `id`, `name`, `inferred`. Продукт: `id`, `category_id`, `name`, `description`, `price`, `currency`, `portion`, `source_images`, `needs_review`. ID назначаются по порядку внутри результата; они не являются постоянными идентификаторами между повторными распознаваниями. `source_images` — номера фото от 1.

Названия и описания сохраняются на языке меню. Отсутствующие значения — `null`; неизвестная цена/валюта требует проверки. Заголовки меню становятся категориями; при отсутствии заголовков Grok предлагает категории с `inferred: true`. Промпт требует объединять очевидные повторы на пересекающихся фото и сохранять варианты с разными порциями/ценами. Точность этого поведения ещё нужно проверить на реальных изображениях.

Невалидный JSON или неверная ссылка на категорию останавливают узел проверки с понятной ошибкой. Пустой распознанный список возвращает `empty` и предупреждение. Эта версия занимается только извлечением продуктов и категорий; последующие этапы остаются в плане проекта.

Локальная проверка: структура YAML и ссылки узлов, соответствие выходов, кириллица, связи категорий, JSON с Markdown-обёрткой, пустое меню, неизвестная цена, предположенная категория, отклонение повреждённого JSON, отрицательных/строковых/NaN цен и неверных типов. Исходная 0.0.1 не изменена. Реальное распознавание и совместимость импорта требуют проверки в Dify после активации x.ai.
