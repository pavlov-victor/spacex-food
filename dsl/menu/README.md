# Menu workflow

Текущий импортируемый файл — [0.0.3.yml](0.0.3.yml), приложение `spacex-menu`.

| Версия | Изменение |
| --- | --- |
| 0.0.1 | Побайтовая копия исходного экспорта из `dsl/0.0.1.yml` |
| 0.0.2 | Побайтовая копия распознавания меню из `dsl/0.0.2.yml` |
| 0.0.3 | Выделение в отдельное приложение `spacex-menu`; граф и контракт результата 0.0.2 сохранены |

Вход — `menu_images` (1–5 JPG/PNG одного меню). Выход — `products`, `categories`, `warnings`, `status`, `schema_version`, `menu_json`. Внутренний `schema_version` результата остаётся `0.0.2`, поскольку контракт не изменён.

Каждый элемент `products` можно сериализовать в `product_json` и отправить в [product workflow](../product/README.md). `category_name` при желании добавляется по `category_id` из массива `categories`.

Нужен провайдер Dify `langgenius/x` и его API Key. Подробная инструкция распознавания сохранена в [общем README](../README.md).

Известные замечания 0.0.2 сохраняются: модель может додумать валюту и потерять диакритику; `ok` не подтверждает точность OCR. Проверка результата — [отчёт](../../docs/menu-extraction-review-0.0.2.md). В рамках разделения workflow распознавание не менялось.
