# Разделение работы: UI и логика

Дизайнер отвечает за дизайн и вёрстку страниц. Агент логики отвечает за типы, валидацию, операции с данными, hooks, интеграции, Dify и инфраструктуру.

| Область | Владелец |
| --- | --- |
| `frontend/src/App.tsx`, будущая `src/pages/` | Дизайнер: страницы, навигация, состояние открытых диалогов и форм |
| `frontend/src/components/`, CSS, `src/assets/`, `public/` | Дизайнер: компоненты и оформление |
| `frontend/src/domain/` | Логика: общие типы и валидация |
| `frontend/src/data/` | Логика: доступ к данным, сетевые запросы, адаптеры |
| `frontend/src/hooks/` | Логика: загрузка, операции, ошибки, состояние запросов |
| `frontend/src/fixtures/` | Логика: явно демонстрационные данные |
| `frontend/convex/` (будет создан при подключении) | Логика: schema, queries, mutations, actions, серверная проверка доступа |
| `dsl/`, `render.yaml`, документация интеграций | Логика / инфраструктура |
| `main.tsx`, `package.json`, lock-файл, общие конфиги | Согласовываем изменения; зависимости добавляет один участник за раз |

## Контракт для дизайнера

Импортировать hook `useProducts` из `@/hooks/use-products`:

```tsx
const { products, isLoading, isSaving, error, createProduct } = useProducts();
const result = await createProduct({
  name: 'Karađorđeva šnicla',
  category: 'Main dishes',
  price: 1200,
  description: '',
});
if (result.ok) closeDialog();
else showError(result.error);
```

- `products`: `Product[]`; типы `Product` и `CreateProductInput` в `@/domain/product`.
- `isLoading`: показывать состояние загрузки; `isSaving`: блокировать повторную отправку.
- `error`: ошибка начальной загрузки. `createProduct` возвращает `{ ok: true, product }` либо `{ ok: false, error }`.
- Поиск: `filterProducts(products, search)` из `@/domain/product`.
- Форма превращает значения полей в `CreateProductInput`; бизнес-валидация и хранение находятся за hook.
- Страницы не импортируют Convex/Dify SDK и не используют `fetch`, ключи или `localStorage` напрямую. Изменение транспорта не должно требовать переписывать вёрстку.
- Текущий адаптер в `src/data/products.ts` использует localStorage и возвращает Promise. Convex ещё не подключён; реалтайм-подписка будет реализована внутри hook с сохранением его публичного контракта.
- Chart fixtures в `@/fixtures/dashboard` предназначены только для демо.

## Git

- После коммита этого разделения дизайнер начинает ветку `feat/crm-ui` от актуального `main`; логика развивается в `feat/crm-data` или тематических ветках.
- На разных компьютерах использовать отдельные клоны. На одной машине — отдельные worktrees, а не переключать ветку в общей папке работающего коллеги.
- PR делать небольшими. Типы и сигнатуры hooks менять отдельным согласованным коммитом, сохраняя совместимость по возможности.
- Не форматировать весь репозиторий и не редактировать чужие страницы ради подключения API. Один раз привязанный hook остаётся границей.
- Тесты логики добавлять отдельными файлами. Общие браузерные тесты менять при согласованном изменении пользовательского сценария.

Текущий `App.tsx` один раз обновлён для использования hook. Дальнейшая вёрстка принадлежит дизайнеру. Документ описывает договорённость; защита путей через GitHub не настроена.
